Background

Why does the embed require authentication?

IBM watsonx Orchestrate embedded chat security is enabled by default on every instance. Until either:

  • A valid RSA public key is registered with the tenant (secured mode), or
  • Security is explicitly disabled (unsecured mode)

…every chat authentication attempt returns HTTP 401 with WXO-PROXY-10080E ("kid is not found in the customer's token"), which the widget surfaces as the "Authentication Error / Agent fetching failed" banner you see in the screenshot.

The widget loads (wxoLoader.js → HTTP 200) but the auth ticket call fails. This is a tenant configuration issue, not a code error.

One-time tenant setup

Log in at eu-de.watson-orchestrate.cloud.ibm.com → profile icon → Administration → Settings → Embed Security → toggle Security: OFF → confirm warning → Save.

Minimal embed code (10 lines)

HTML — paste near </body> 
<!-- Container element -->
<div id="wxo-chat-root"></div>

<script>
window.wxOConfiguration = {
  orchestrationID: "YOUR_ORCHESTRATION_ID",
  hostURL:         "https://eu-de.watson-orchestrate.cloud.ibm.com",
  rootElementID:   "wxo-chat-root",
  showLauncher:    true,
  crn:             "YOUR_CRN",
  deploymentPlatform: "ibmcloud",
  chatOptions: { agentId: "YOUR_AGENT_ID", agentEnvironmentId: "YOUR_ENV_ID" }
};
setTimeout(function(){
  const s=document.createElement("script");
  s.src=window.wxOConfiguration.hostURL+"/wxochat/wxoLoader.js?embed=true";
  s.addEventListener("load",()=>wxoLoader.init()); document.head.appendChild(s);
},0);
</script>

Step 1 — Generate RSA key pair

# Generates keys/wxo_embed_private.pem + keys/wxo_embed_public.pem
bash scripts/generate_rsa_keys.sh

# Add to .env
echo "EMBED_PRIVATE_KEY_FILE=keys/wxo_embed_private.pem" >> .env

Step 2 — Upload public key to wxO tenant

eu-de.watson-orchestrate.cloud.ibm.com → Administration → Settings → Embed Security → toggle Security: ON → paste keys/wxo_embed_public.pem → Save.

Step 3 — Start the JWT signing server

source venv/bin/activate
python scripts/jwt_server.py    # listens on :3001

Step 4 — identityToken callback in the embed

// The only difference from unsecured: add identityToken to chatOptions
window.wxOConfiguration = {
  // ... same fields as unsecured ...
  chatOptions: {
    agentId:            "YOUR_AGENT_ID",
    agentEnvironmentId: "YOUR_ENV_ID",

    identityToken: {
      getToken: async function() {
        const res  = await fetch("http://localhost:3001/api/token");
        const data = await res.json();
        return data.token;   // raw JWT string
      }
    }
  }
};

Network requests made by the widget

RequestMethodAuthNotes
/wxochat/wxoLoader.js?embed=true GETNone Loader script from hostURL CDN — always HTTP 200
/instances/{id}/v1/auth/ticket GET JWT (secured) / anon (unsecured) Session ticket from API backend — the failing call
/instances/{id}/v1/chat POST Session ticket Streaming chat completions
http://localhost:3001/api/token GET/POST None (backend-internal) JWT signing server — secured mode only

Error code reference

CodeHTTPCauseFix
WXO-PROXY-10080E401 "kid is not found in the customer's token" — no public key registered Upload public key to Embed Security tab, or disable security
WXO-PROXY-10055E401 "Not authenticated" — missing Authorization header Ensure identityToken.getToken returns a valid JWT string
WXO-PROXY-15008E400 "IAM-API_KEY is missing" — wrong endpoint called Check hostURL vs instanceUrl — use portal URL for hostURL
Authentication Error (UI)— Widget cannot complete auth ticket flow Check browser DevTools Network tab for underlying HTTP error
Agent fetching failed (UI)— Auth succeeded but agent not in Live state Run: orchestrate agents deploy --name ibm_bob_assistant

Content Security Policy

The CSP differs between modes. The secured mode adds http://localhost:3001 to connect-src so the identityToken callback can reach the JWT server.

Unsecured — connect-src additions 
connect-src 'self'
            https://eu-de.watson-orchestrate.cloud.ibm.com
            https://api.eu-de.watson-orchestrate.cloud.ibm.com
            https://*.eu-de.watson-orchestrate.cloud.ibm.com
            wss://eu-de.watson-orchestrate.cloud.ibm.com;
Secured — adds JWT server origin 
connect-src 'self'
            http://localhost:3001           ← JWT signing server
            https://eu-de.watson-orchestrate.cloud.ibm.com
            https://api.eu-de.watson-orchestrate.cloud.ibm.com
            ...;
