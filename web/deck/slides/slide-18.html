Section 04

JWT token lifecycle

Token claims (RS256 payload)

{
  "iss": "ibm_bob_assistant_demo",
  "sub": "user-id or anon-uuid8",
  "aud": "watsonx-orchestrate",
  "iat": 1700000000,  // issued-at
  "exp": 1700003600,  // expiry
  "jti": "uuid-v4",    // replay prev.
  "name": "Display name" // optional
}

All fields follow the IBM watsonx Orchestrate JWT specification.

Token flow — browser to wxO

  1. Browser loads page with wxO widget script
  2. wxoLoader.init() is called
  3. Widget calls identityToken.getToken()
  4. Browser fetches GET :3001/api/token
  5. jwt_server.py signs token with private key
  6. Widget sends JWT to wxO auth endpoint
  7. wxO verifies JWT with uploaded public key
  8. Session established — chat is active
  9. Widget auto-refreshes token before expiry

Environment variables

# Required
EMBED_PRIVATE_KEY_FILE=
  keys/wxo_embed_private.pem

# Optional (with defaults)
JWT_SERVER_PORT=3001
JWT_EXPIRY_SECONDS=3600
JWT_AUDIENCE=watsonx-orchestrate
ALLOWED_ORIGINS=
  http://localhost:8080

All vars read from .env at startup. Never hard-coded. Maximum expiry: 7100 s (IBM hard limit).
