1. Executive Overview & Scope

This repository implements a modular, enterprise-grade dual-agent ecosystem on IBM watsonx Orchestrate (wxO) deployed into cloud instance aam-wxo-be (75c2cabb-2b02-4d65-8127-a9cc65d1ee46).

Agent 1: ibm_bob_assistant

Native watsonx Orchestrate conversational agent grounded directly in managed knowledge base collections covering IBM Bob documentation.

Agent 2: ibm_doc_assistant

Custom Python tool-calling agent with an automated scraping, semantic chunking, and TF-IDF vector similarity search pipeline.

Security & Web Chat

Lightweight RSA-256 JWT signing daemon and local Web Chat UI client configured for immediate testing and embed evaluation.

3. System Architecture & Technical Flow

The system connects client applications, local services, and IBM Cloud watsonx Orchestrate through a clean multi-tier architecture:

Client Layer:
  Web Browser (Port 8000) <---> JWT Security Proxy (Port 3000) <---> watsonx Orchestrate Cloud
  Terminal CLI Agent      <---> Local Vector Store (83 Chunks)

Data Ingestion Pipeline:
  Upstream Docs / Files   ---> Scraper Engine ---> Semantic Chunker ---> TF-IDF Vector Index ---> wxO Deploy

Cloud Tool Isolation Resilience: Cloud @tool functions run inside stateless microservices. To prevent FileNotFoundError exceptions on ibm_doc_store.json, the tool implementation includes an embedded fallback corpus providing complete offline/cloud coverage.

4. IBM Doc Agent Package Architecture

The src/agents/ibm_doc_agent/ Python package contains modular, type-hinted components:

  • models.py: Pydantic schemas defining Document, Chunk, SearchResult, and request/response models.
  • scraper.py: HTML parsing, header/footer removal, content normalization, and local file reading.
  • chunker.py: 500-word sliding windows with 50-word overlaps, preserving sentence and paragraph structures.
  • vector_store.py: Standalone TF-IDF cosine similarity search engine with persistence.
  • tools.py: watsonx Orchestrate @tool definitions (search_ibm_live_docs and get_ibm_doc_by_url).
  • agent.py: Standalone conversational agent with ANSI color output for terminal use.

8. Master Automation Script Reference

The single-entrypoint script scripts/automate.sh manages all lifecycle tasks:

Command Purpose
./scripts/automate.sh setup Initializes Python venv, directories, permissions, and installs dependencies.
./scripts/automate.sh ingest Runs document scraper, re-chunks text, and generates ibm_doc_store.json.
./scripts/automate.sh deploy Deploys Python tools and agent definitions to watsonx Orchestrate.
./scripts/automate.sh refresh Executes the full end-to-end sync, re-chunking, and re-deployment pipeline.
./scripts/automate.sh serve Launches JWT auth server (Port 3000) and Web Chat interface (Port 8000).
./scripts/automate.sh chat Launches the interactive terminal CLI chat session.
./scripts/automate.sh status Displays vector store chunk counts, cloud environment variables, and agent state.
./scripts/automate.sh test Runs automated unit test suites for tools, scrapers, and deployers.
./scripts/automate.sh clean Cleans temporary files, logs, and python bytecode caches.
